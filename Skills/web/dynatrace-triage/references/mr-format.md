# MR Format

Use this canonical MR/PR body. Keep the v1-style `Error` section and stack trace, but include reviewer-grade reasoning sections as part of the standard body.

```text
Title: fix(<scope>): <short summary> (<error_id>)

## Error
- **Error ID:** <error_id>
- **Severity:** <severity>
- **Signal:** <signal>
- **Runtime error:** <error_message>
- **Affected users:** <affected_users>
- **Occurrence count:** <count>
- **Impacted teams:** <teams>
- **Top pages:**
  - <top_page_1>
  - <top_page_2>
- **Browsers:** <browsers>
- **Replay:** <replay_url>
- **Error details:** <error_detail_url>

<details>
<summary>Sample stack trace</summary>

```text
<sample_stack_trace>
```

</details>

## Root Cause
- **Symptom:** <what failed at runtime>
- **Trigger:** <the immediate scenario that triggered the failure>
- **Actual root cause:** <the architectural/runtime cause>
- **Why this happened in product/runtime terms:** <short explanation beyond code mechanics>

## Fix Applied
- <concise description of the code change>
- <guard / null check / cleanup / SSR protection / other applied pattern>
- <tests added or updated when relevant>

## Why This Fix
- <why this change is correct>
- <why it is safer than plausible alternatives>

## Regression Risk
- <behavior that changes>
- <behavior that must remain unchanged>
- <possible hidden breakpoints>

## Related Areas To Audit
- <sibling components/modules to inspect>
- <related Dynatrace IDs if duplicate or similar>
- <systemic follow-up suggestion if relevant>
```

## Auto-Heal Attribution (Mode 3 only)

Mode 3 MRs use the canonical body above with two additions. Mode 1 MRs remain
exactly as-is (no marker).

1. Marker line at the very top of the body:

```text
> 🤖 Auto-generated by dynatrace-triage auto-heal (run <run_id>)
```

2. Footer section appended after `## Related Areas To Audit`:

```text
## Auto-Heal Attribution
- **Run:** <run_id>
- **Registry:** ~/.claude/dynatrace-triage-workspace/<repo-name>/registry.json
- **Source confidence:** <high|medium>
- **Fix confidence:** <high|medium> (assumptions: <listed when medium>)
- **Branch point:** <origin/master SHA the branch was cut from>
- **Duplicate group:** <grp-id + sibling error IDs, or "none">
- **Reproduction:** <spec name proving the failure path, or explicit reason reproduction was infeasible>
```

Labels on creation: `--label "auto-heal,dynatrace-triage"`.

Rules:
- If a CSV row is available, include the row metadata above in the `Error` section.
- Exclude these CSV fields from the MR body: `⚡ Intensity`, `⭐ Priority`, `📱 Devices`, `Assignee`, `Dev Comments`, `Status`.
- Preserve this presentation style:
  - bullet list for `Error`
  - collapsible sample stack trace
  - reviewer-grade sections after `Error`
  - no metadata table
  - no `Validation` section
