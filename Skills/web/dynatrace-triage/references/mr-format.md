Use this canonical MR/PR body. Keep the v1-style `Error` section and stack trace, but include reviewer-grade reasoning sections as part of the standard body.

## Auto-Heal Attribution (Mode 3 only)

Mode 3 MRs use the canonical body above with two additions. Mode 1 MRs remain
exactly as-is (no marker).

1. Marker line at the very top of the body:

```text
> 🤖 Auto-generated by dynatrace-triage auto-heal (run <run_id>)
```

2. Footer section appended after `## Related Areas To Audit`:

```text
## Auto-Heal Attribution
- **Run:** <run_id>
- **Registry:** <the actual registry path used for this run — `$REGISTRY_PATH/registry.json` if set, else `~/.claude/dynatrace-triage-workspace/<repo-name>/registry.json`>
- **Source confidence:** <high|medium>
- **Fix confidence:** <high|medium> (assumptions: <listed when medium>)
- **Branch point:** <origin/master SHA the branch was cut from>
- **Duplicate group:** <grp-id + sibling error IDs, or "none">
- **Reproduction:** <spec name proving the failure path, or explicit reason reproduction was infeasible>
```

Labels on creation: `--label "auto-heal,dynatrace-triage"`.

Rules:
- If a CSV row is available, include the row metadata above in the `Error` section.
- Exclude these CSV fields from the MR body: `⚡ Intensity`, `⭐ Priority`, `📱 Devices`, `Assignee`, `Dev Comments`, `Status`.
- Preserve this presentation style:
  - bullet list for `Error`
  - collapsible sample stack trace
  - reviewer-grade sections after `Error`
  - no metadata table
  - no `Validation` section

## Worked example (Mode 3, filled in)

```text
Title: fix(order-summary): guard SimpleChanges before reading currentValue (261e721354a6680a)

> 🤖 Auto-generated by dynatrace-triage auto-heal (run heal-2026-07-10-1)

## Error
- **Error ID:** 261e721354a6680a
- **Severity:** High
- **Signal:** Recurring
- **Runtime error:** TypeError: Cannot read properties of undefined (reading 'currentValue')
- **Affected users:** 178
- **Occurrence count:** 1,198
- **Impacted teams:** Pharmacy, Core, Insurance
- **Top pages:**
  - /checkout
  - /checkout/address
- **Browsers:** Chrome, Chrome Mobile, Android WebView

<details>
<summary>Sample stack trace</summary>

```text
at OrderSummaryComponent.ngOnChanges (order-summary.component.ts:88)
```

</details>

## Root Cause
- **Symptom:** ngOnChanges throws when `changes['quantity']` is absent.
- **Trigger:** parent passes a partial `SimpleChanges` object on a fast re-render.
- **Actual root cause:** the component reads `changes.quantity.currentValue` without checking `changes.quantity` exists first.
- **Why this happened in product/runtime terms:** rapid cart-quantity taps fire more change-detection cycles than the parent emits full change objects for.

## Fix Applied
- Added `changes.quantity &&` guard before dereferencing `currentValue`.
- Added a regression spec covering the partial-changes case.

## Why This Fix
- Restores the correct contract: `currentValue` should only ever be read when `quantity` is actually present in the changes.
- Safer than a broad `try/catch`, which would mask other genuine errors in the same method.

## Regression Risk
- Behavior unchanged for the normal case (full SimpleChanges object).
- No hidden breakpoints identified — the guard is a pure narrowing, not a logic change.

## Related Areas To Audit
- `order-summary-mobile.component.ts` uses the same pattern — not yet reported by Dynatrace, worth a follow-up check.

## Auto-Heal Attribution
- **Run:** heal-2026-07-10-1
- **Registry:** <the actual registry path used for this run>
- **Source confidence:** high
- **Fix confidence:** high
- **Branch point:** 4f2a9c1
- **Duplicate group:** none
- **Reproduction:** order-summary.component.spec.ts — "should not throw when quantity change is partial"
```
